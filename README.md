# バーコード連動レシート写真システム（試作）

プリンターやバーコードリーダーがまだ無い段階で、PCのカメラを使ってバーコードを読み取り、
対応する写真から「レシートに印字するイメージ」を作成・確認できる試作アプリです。
サーバー不要・PCのブラウザだけで動作します。

## 使い方（最短）

1. `receipt-photo-system` フォルダを丸ごとPCに保存する
2. `index.html` をダブルクリックして Google Chrome で開く
3. 「①スキャン確認」タブで「カメラ開始」を押す（カメラ使用の許可を求められたら許可）
4. まだ本物のバーコードが無い場合は、先に「③テスト用バーコード作成」タブで
   サンプルバーコード（SAMPLE-0001 など）を画面に表示し、スマホやタブレットに
   映してPCのカメラで読み取ってみてください
5. 対応する写真が見つかると「スキャン中の一覧」に1件追加されます。カメラは止まらないので、
   続けて別のバーコードも次々読み取れます（複数のバーコードを1回のお会計にまとめたい場合など）
6. 読み取りたいバーコードをすべて読み終えたら「レシートを作成」を押すと、一覧の内容が
   まとめて1枚のレシートプレビューになります
7. 「これでOK」で履歴に記録（一覧はクリアされます）、「やり直す（一覧に戻る）」で一覧に戻って
   バーコードを追加・削除、「PNGをダウンロード」で画像として保存できます

対応ブラウザは **Google Chrome推奨**です（Edgeでも動作しますが、Chromeで動作確認しています）。
インターネット接続が必要です（バーコード読み取り・作成ライブラリをCDNから読み込むため）。

**スマホで使いたい場合**は、上記の方法（`index.html` を直接開く）ではカメラが使えません。
下の「スマホで使う（一時公開・アカウント不要）」をご覧ください。

## スマホで使う（一時公開・アカウント不要）

スマホのブラウザでカメラ（`getUserMedia`）を使うには、`index.html` を直接開く方式（`file://`）ではなく、
**`https://` で配信されたページ**である必要があります（Safari・Chromeどちらも同様の制限があります）。
そこで、PC上でこのフォルダを一時的にWeb公開して、そのURLをスマホで開く方法を使います。
無料・アカウント登録不要の「Cloudflare Quick Tunnel」という仕組みを使います。

**注意**: 発行されるURLは推測されにくいランダムな文字列ですが、稼働中は誰でもアクセスできる状態になります。
検証用の一時的な仕組みなので、使い終わったら両方のターミナルを閉じて（`Ctrl + C`）公開を止めてください。
再度起動するとURLは毎回変わります。ずっと同じURLで使いたい場合は、無料の静的ホスティング
（Cloudflare Pages・GitHub Pagesなど）への常設公開をご検討ください（ご希望であれば別途ご案内します）。

### 手順（Mac / ターミナルを2つ使います）

**ターミナル1: ローカルサーバーを起動**

```
cd receipt-photo-system
python3 -m http.server 8000
```

そのまま起動したままにしておきます（閉じないでください）。

**ターミナル2: 公開用トンネルを起動**

`cloudflared` がまだ無い場合は、最初に1回だけインストールします（Homebrewがあれば）。

```
brew install cloudflared
```

（Homebrewが無い場合は https://github.com/cloudflare/cloudflared/releases から
`cloudflared-darwin-amd64.pkg`（Intel Mac）または対応するパッケージをダウンロードしてインストールしてください。）

インストールできたら、トンネルを起動します。

```
cloudflared tunnel --url http://localhost:8000
```

しばらくすると、ターミナルに `https://◯◯◯◯.trycloudflare.com` のようなURLが表示されます。
このURLをスマホのブラウザ（Safari / Chrome）で開いてください。Wi-Fiでもモバイル回線でもアクセスできます。

### スマホでの使い方

スマホなど画面の狭い端末で開くと、②対応表・③テスト用バーコード作成のタブは自動的に非表示になり、
「①スキャン確認」の画面だけが表示されます（登録などの管理操作はPCで行う想定のため）。

1. 上記のURLをスマホのブラウザで開く
2. 「カメラ開始」をタップし、カメラ使用を許可する
3. バーコードを読み取ると「スキャン中の一覧」に追加される（カメラは止まらないので、複数の
   バーコードを続けて読み取れる）
4. 読み終えたら「レシートを作成」をタップすると、一覧の内容をまとめたレシートプレビューが表示される
5. 「これでOK」で確定、「PNGをダウンロード」で保存
   - **iPhoneでダウンロードがうまく動かない場合**は、隣の「新しいタブで開く（iPhoneは長押しで保存）」を
     使ってください。画像だけが表示されるので、長押しして「写真に追加」または「画像を保存」を選べば保存できます。

※スマホでちゃんと写真が表示されるのは、`mapping.js`（＋`photos-data.js`）に登録されている
バーコードだけです。PCの「一時登録」だけで登録したものは、上の「一時登録をスマホなど他の端末にも
反映させる（書き出し機能）」の手順でmapping.jsに書き出してアップロードするまでスマホには出てきません。

## 常時公開する（GitHub Pages・無料アカウント要）

「毎回トンネルを起動するのが面倒」「いつも同じURLでスマホからアクセスしたい」という場合は、
GitHub Pages でこのフォルダを常設公開できます。無料のGitHubアカウントが必要です。

**重要な注意**: GitHub の無料プランでPagesを公開するには、リポジトリを **Public（公開）** に
する必要があります。Publicにすると、このフォルダの中身（写真も含む）は **URLを知っていれば誰でも
閲覧できる状態** になります。有料プランでもリポジトリをPrivateにできるだけで、公開されたサイト自体の
閲覧に認証をかけるにはGitHub Enterpriseが必要です。今はサンプル写真だけですが、実際の写真を
登録して常設公開する場合はこの点にご注意ください（非公開にしたい場合は、都度公開する
Cloudflare Quick Tunnel運用のままにするか、Cloudflare Pages + Cloudflare Access
のようなアクセス制限付きの方法をご検討ください。ご希望があればそちらの手順もご用意します）。

### 手順（ブラウザだけ・gitコマンド不要）

1. https://github.com で無料アカウントを作成してログインする
2. 右上の「+」→「New repository」で新しいリポジトリを作成する
   - Visibility は **Public** を選ぶ（Privateだと無料プランではPages公開できません）
3. 作成したリポジトリの画面で「Add file」→「Upload files」を開く
4. この `receipt-photo-system` フォルダの**中身**（`index.html`・`app.js`・`style.css`・
   `mapping.js`・`photos-data.js`・`.nojekyll`・`README.md`・`photos`フォルダ・`tools`フォルダ）を
   まとめてドラッグ&ドロップする（フォルダごとではなく、中身を選んでください）
5. 画面下の「Commit changes」でアップロードを確定する
6. リポジトリの「Settings」→左メニューの「Pages」を開く
7. 「Build and deployment」の Source を **「Deploy from a branch」**、
   Branch を **「main」/「/(root)」** にして「Save」
8. 1〜3分待つと、ページ上部に `https://ユーザー名.github.io/リポジトリ名/` というURLが表示される
9. そのURLをスマホのブラウザで開けば、PCと同じ操作（カメラ開始→読み取り→確認→ダウンロード）が使えます

写真や対応表(`mapping.js`)を更新したときは、同じ「Add file」→「Upload files」で該当ファイルを
アップロードし直せば数分後にサイトへ反映されます（`photos`フォルダの画像を追加・変更した場合は、
アップロード前に手元で `python3 tools/build_photos_data.py` を実行して `photos-data.js` も
作り直し、それも一緒にアップロードしてください）。

## 実際の写真が届いたら（対応表の登録）

`mapping.js` を開いて、以下の形式で「バーコードの値」と「写真ファイル」を書き並べてください。
1枚だけの場合は `photo`、複数枚を1つのバーコードに対応させたい場合は `photos`（配列）を使います。

```js
window.BARCODE_MAP = [
  {
    barcode: "4912345678904",       // バーコードに埋め込まれている値（スキャンされる文字列）
    photo: "photos/product001.jpg", // 1枚だけの場合
    label: "商品名など（任意）"
  },
  {
    barcode: "4912345678911",
    photos: ["photos/product002_1.jpg", "photos/product002_2.jpg"], // 複数枚の場合
    label: "商品名など（任意）"
  },
  // ...必要な数だけ追加
];
```

- 写真ファイルは `photos` フォルダにコピーしてください（jpg/png対応）
- `barcode` は読み取られた文字列と完全一致で照合します（前後の空白は自動で無視されます）
- **`photos` フォルダの中身を追加・変更したら、次のコマンドを1回実行してください**（Pythonが入っているPCの場合）。
  レシート画像の「PNGをダウンロード」や「グレースケール／白黒2値」表示を正しく動かすための下準備です（`photos-data.js` を作り直します）。

  ```
  cd receipt-photo-system
  python3 tools/build_photos_data.py
  ```

- 保存・実行して `index.html` を再読み込みすれば反映されます
- 私（Claude）に写真一覧とファイルをお送りいただく運用の場合は、`mapping.js` の更新とあわせてこのコマンドもこちらで実行してからお渡しします。自分で編集されない場合は特に気にしていただく必要はありません。

バーコード値と写真の対応リスト（Excel/CSVなど）をいただければ、私の方で `mapping.js` に
反映することも可能です。その場合は「①どのバーコード値に②どの写真ファイルを対応させるか」が
わかる一覧と、写真ファイル一式をお送りください。

## 対応しているバーコード

1次元バーコード（JAN/EANコード、CODE128、CODE39、UPCなど）に加えて、**QRコードにも対応しています**。
バーコードの「値（文字列）」を対応表と照合しているだけなので、どちらの形式で作っても対応表
（mapping.js・一時登録）の仕組みはまったく同じです。

スマホなどのカメラで読み取る場合は、**QRコードのほうが読み取りに強い**のでおすすめです。
QRコードは誤り訂正機能を持っており、多少ボケていたり画面のモアレで一部が欠けていても
正しく読み取れることが多いのに対し、1次元バーコードは元々レジなどの専用スキャナーでの
読み取りを想定した設計のため、スマホのカメラのような手持ちのカメラでは条件が悪いと
読み取れないことがあります。実物の商品バーコード（JAN/EANなど）をそのまま使いたい場合を
除いて、これから新しく紙のタグ・チケットなどを作る場合はQRコードを使うことを検討してください。

## 動作確認用のミニ機能

- **③テスト用バーコード作成タブ**: 実物のバーコードが無くても、任意の文字列からバーコード画像（QRコード／
  1次元バーコードのどちらも選べます）を作成し、画面表示・印刷ができます。これを別の画面（スマホなど）に
  映してカメラで読み取れば、一通りの動作確認ができます。「サンプル1〜3」ボタンは読み取りに強い
  QRコード版を作成します（比較用に「サンプル1（1次元）」ボタンもあります）。
- **②対応表タブの「一時登録」**: その場で好きな写真（複数枚選択可）をアップロードしてバーコード値と
  紐付けられます。**このPC・このブラウザに保存されるため、ページを再読み込みしても消えません。**
  ただし**この保存場所はブラウザごとに別々**なので、PCで一時登録しただけではスマホ側には表示されません。
  不要になったら、一覧の写真サムネイルの「×」で1枚だけ削除、「登録を削除」でバーコードごとまとめて
  削除、「一時登録をすべて削除」で全件削除できます。
- **一時登録をスマホなど他の端末にも反映させる（書き出し機能）**: 一時登録の下にある
  「mapping.js と photos-data.js を書き出す」ボタンを押すと、今の対応表（mapping.js）＋一時登録の
  内容をまとめた `mapping.js` と `photos-data.js` の2ファイルがダウンロードされます。これをGitHubの
  同名ファイルに上書きアップロードして数分待てば、スマホを含めてどの端末でページを開いても同じ写真が
  表示されるようになります（この2ファイルだけで完結するので、`photos` フォルダへの画像追加は不要です）。
  反映を確認できたら、「一時登録をすべて削除」でこのブラウザ内の一時登録を消して整理しておくと安全です
  （消さなくても動作上は問題ありませんが、対応表タブの表示が二重に見えることがあります）。

## 複数のバーコードを1枚のレシートにまとめる（バーコード複数読み取り対応）

「①スキャン確認」タブはカメラを止めずに次々バーコードを読み取れる仕様です。読み取るたびに
画面右の「スキャン中の一覧」に1件ずつ追加され、同じバーコードを連続で二重に読み取らないよう
短いクールダウン（約1.2秒。未登録バーコードの場合は約3秒）をはさんで自動的に読み取りを再開します。

一覧にたまったバーコードは、行の「削除」ボタンで個別に取り消せます。読み取りたいものが
すべてそろったら「レシートを作成」を押すと、一覧の内容（各バーコードの写真・ラベル・
バーコード画像）をすべて1枚のレシートにまとめてプレビューします（1件だけの場合も同じ
操作で問題なく作成できます）。

プレビュー画面で「これでOK」を押すと履歴に記録され、一覧はクリアされます。「やり直す
（一覧に戻る）」を押した場合は一覧の内容は消えないので、バーコードを追加・削除してから
もう一度「レシートを作成」をやり直せます。「一覧をクリア」で一覧を空に戻すこともできます。

## レシートのデザインについて

上下端がミシン目で切り取ったようなギザギザになっており、実際のレシート用紙に近い見た目に
しています。伝票番号（No.）や日時、区切り線もモノスペースフォントで印字されます。1つの
バーコードに複数枚の写真が登録されている場合は縦に並べて表示され、複数のバーコードを
まとめて読み取った場合は各バーコードの内容（写真・ラベル・バーコード画像）が区切り線を
はさんで縦に並び、上部に「点数: ◯点」も表示されます。

## 印字モードについて

将来レシートプリンター（多くは感熱式・白黒）で印刷することを想定し、①タブの「印字モード」で
カラー／グレースケール／白黒2値（感熱プリンター風の見え方）を切り替えてプレビューできます。
実際に使うプリンターの仕様（用紙幅・解像度・白黒/カラー）が分かれば、より正確に調整できます。

## バーコードが読み取れない・読み取りにくいとき

読み取り精度を上げるため、①スキャン確認タブには以下の機能があります。

- **枠でのガイド表示**: カメラ映像に点線の枠が表示されます。バーコードをこの枠の中に、
  なるべく画面いっぱい・まっすぐ映すと読み取りやすくなります。距離は20〜30cm程度から
  少しずつ近づけて、ピントが合う位置を探してください。遠すぎる・斜めすぎる・
  枠からはみ出している・近づけすぎてピントが合っていない、のいずれかだとうまく
  読み取れないことが多いです。
- **💡 ライト（トーチ）ボタン**: スマホのカメラがフラッシュライトの制御に対応している場合、
  カメラ開始後に「💡 ライト」ボタンが表示されます。暗い場所での読み取りに使ってください
  （非対応の端末では表示されません）。
- **ピント・露出の自動追従**: 対応しているカメラでは、ピントや明るさを継続的に自動調整する
  設定を有効にしています（非対応の環境では自動的に無視されるだけで、動作に影響しません）。
- **手入力での追加**: どうしてもカメラで読み取れない場合（バーコードが破れている・反射する
  素材に印刷されているなど）は、カメラ映像の下にある入力欄にバーコードの値を直接入力し、
  「追加」またはEnterキーで「スキャン中の一覧」に追加できます。カメラで読み取った場合と
  まったく同じように扱われます。

それでも読み取りにくい場合は、以下も確認してみてください。

- 部屋を明るくする、または上記のライトボタンを使う
- バーコードに影が映り込んでいないか確認する（自分の手やスマホの影に注意）
- バーコードを平らな面に置く、または紙を軽く伸ばしてシワ・反りをなくす
- カメラのレンズ部分の汚れ・指紋を拭き取る
- 「③テスト用バーコード作成」タブで作った鮮明なバーコードで、まず正常に読み取れるか
  切り分けてみる（正常に読み取れる場合は印刷物側の品質が原因の可能性が高いです）

### スマホなど「別の画面」に表示したバーコードを読み取る場合の注意（モアレ）

動作確認のために、あるスマホ／PCの画面にバーコードを表示し、それを別のスマホやPCの
カメラで読み取ってテストすることがあると思います。この「画面 → カメラ」の組み合わせは、
紙に印刷したバーコードを読み取る場合に比べて本質的に読み取りにくい方法です。
表示側の画面の画素と、読み取る側のカメラの画素が細かい格子状に干渉し合い、
縞模様（モアレ）やちらつきが写り込んでバーコードの線が歪んでしまうことがあるためです。
特に画面にカメラをかなり近づけた場合（10〜20cm程度）に強く出やすい現象です。

改善策（効果が高い順）：

1. **1次元バーコードの代わりにQRコードを使う（根本的な対策としておすすめ）**
   「③テスト用バーコード作成」タブでQRコードを作成してください（サンプル1〜3ボタンは
   QRコード版になっています）。QRコードは誤り訂正機能を持っているため、多少のモアレや
   ボケがあっても正しい値を読み取れることが多く、スマホのカメラで画面を撮って読み取る
   という今回のような使い方にはQRコードのほうが根本的に向いています。実物の商品バーコード
   （JAN/EANなど、すでに印刷されているもの）をそのまま使う必要がある場合を除き、これから
   新しく作るタグやチケットにはQRコードの採用を検討してください。
2. 一度画面から離し、20〜30cm程度から少しずつ近づけてピントが合う位置を探す
   （近づけすぎるとモアレとピンボケの両方が起きやすくなります）
3. 表示側の画面の明るさを上げる／画面の映り込み・反射を避ける
4. 「③テスト用バーコード作成」タブでバーコードをできるだけ大きく表示する
   （値の文字数が少ないほど、また画面いっぱいに表示するほど改善しやすいです）
5. 可能であれば「③テスト用バーコード作成」タブの「画像をダウンロード」または「印刷する」で
   一度紙に印刷し、印刷物を読み取ってみる（実際の運用に最も近い条件で確認できます。
   モアレの影響を受けないため、通常はこちらのほうが安定して読み取れます）

なお、以前は認識対象の形式にCODABAR・ITFも含めていたことがありましたが、これらは
他形式（CODE128など）のバーコードの一部を誤って別の値として読み取ってしまう
「誤読」を起こしやすいため、現在は主要な商品バーコード形式（CODE128・EAN-13/8・
UPC-A/E・CODE39）のみを対象にしています。そのため、上記のようにモアレなどで
本来の形式として読み取れない状況では、以前のように（間違った値であっても）
何かしら読み取れてしまうことはなくなり、正直に「読み取れない」という結果になります。
これは誤ったデータが記録されるのを防ぐための意図した挙動です。

## カメラが起動しない場合

- ブラウザのアドレスバー付近に出るカメラ許可ダイアログで「許可」を選んでください
- 一度拒否してしまった場合は、ブラウザのサイト設定からカメラ許可をリセットしてください
- `index.html` を直接開く方法でカメラが動作しない場合は、フォルダ内で以下のようにローカルサーバーを
  起動してから `http://localhost:8000` を開いてみてください（Python が入っているPCの場合）。

```
cd receipt-photo-system
python3 -m http.server 8000
```
