# 番号連動レシート写真システム（試作）

番号（バーコードなどに使う値）を入力すると、対応する写真から「レシートに印字するイメージ」を
作成・確認できる試作アプリです。サーバー不要・ブラウザだけで動作します。

以前はカメラでバーコードを読み取る方式でしたが、読み取り精度が環境によって不安定だったため、
現在は**番号を直接入力する方式**に変更しています。カメラを使わないため、PCでもスマホでも
（特別な許可や設定なしに）同じように使えます。

## 使い方（最短）

1. `receipt-photo-system` フォルダを丸ごと保存する
2. `index.html` をダブルクリックしてブラウザ（Google Chrome推奨）で開く
3. 「①番号入力」タブの入力欄に番号（例: `SAMPLE-0001`）を入力し、「追加」またはEnterキーを押す
4. 対応する写真が見つかると、右側の「追加した一覧」に1件追加されます。続けて何個でも
   入力できます（複数の番号を1回のお会計にまとめたい場合など）
5. 入力し終わったら「レシートを作成」を押すと、一覧の内容がまとめて1枚のレシートプレビューに
   なります
6. 「これでOK」で履歴に記録（一覧はクリアされます）、「やり直す（一覧に戻る）」で一覧に戻って
   番号を追加・削除、「PNGをダウンロード」で画像として保存、「🖨️ 印刷する」でそのまま印刷
   （PCでプリンターに接続している場合）できます

対応ブラウザは **Google Chrome推奨**です（Edgeでも動作しますが、Chromeで動作確認しています）。
バーコード画像の生成（レシート上の飾り・③タブのラベル作成）にのみ、インターネット接続で
読み込む外部ライブラリを使っています。

## スマホで使う

カメラを使わなくなったため、スマホでの利用もシンプルになりました。特別なサーバーやHTTPS化は
不要です。番号を入力するだけなので、以下のどちらの方法でも使えます。

### 方法A: フォルダをスマホに転送してそのまま開く（一番簡単）

`receipt-photo-system` フォルダを丸ごと、AirDropやクラウドストレージ（Google Drive・iCloud
など）経由でスマホに転送し、その中の `index.html` をスマホのブラウザで開くだけで使えます。
サーバーを立てる必要も、URLを発行する必要もありません。

### 方法B: GitHub Pagesで常設公開する（毎回転送せず、常に同じURLで使いたい場合）

登録した写真を更新するたびにフォルダを転送し直すのが面倒な場合は、無料のGitHubアカウントで
このフォルダを常設公開できます。常に同じURLをスマホのブックマークから開けるようになります。

**重要な注意**: GitHub の無料プランでPagesを公開するには、リポジトリを **Public（公開）** に
する必要があります。Publicにすると、このフォルダの中身（写真も含む）は **URLを知っていれば誰でも
閲覧できる状態** になります。有料プランでもリポジトリをPrivateにできるだけで、公開されたサイト自体の
閲覧に認証をかけるにはGitHub Enterpriseが必要です。今はサンプル写真だけですが、実際の写真を
登録して常設公開する場合はこの点にご注意ください（非公開にしたい場合は、都度フォルダを転送する
方法Aのままにするか、アクセス制限付きのホスティング方法をご検討ください。ご希望があれば
別途ご案内します）。

#### 手順（ブラウザだけ・gitコマンド不要）

1. https://github.com で無料アカウントを作成してログインする
2. 右上の「+」→「New repository」で新しいリポジトリを作成する
   - Visibility は **Public** を選ぶ（Privateだと無料プランではPages公開できません）
3. 作成したリポジトリの画面で「Add file」→「Upload files」を開く
4. この `receipt-photo-system` フォルダの**中身**（`index.html`・`app.js`・`style.css`・
   `mapping.js`・`photos-data.js`・`.nojekyll`・`README.md`・`photos`フォルダ・`tools`フォルダ）を
   まとめてドラッグ&ドロップする（フォルダごとではなく、中身を選んでください）
5. 画面下の「Commit changes」でアップロードを確定する
6. リポジトリの「Settings」→左メニューの「Pages」を開く
7. 「Build and deployment」の Source を **「Deploy from a branch」**、
   Branch を **「main」/「/(root)」** にして「Save」
8. 1〜3分待つと、ページ上部に `https://ユーザー名.github.io/リポジトリ名/` というURLが表示される
9. そのURLをスマホのブラウザで開けば、番号入力→レシート作成→確認→ダウンロードが使えます

写真や対応表(`mapping.js`)を更新したときは、同じ「Add file」→「Upload files」で該当ファイルを
アップロードし直せば数分後にサイトへ反映されます（`photos`フォルダの画像を追加・変更した場合は、
アップロード前に手元で `python3 tools/build_photos_data.py` を実行して `photos-data.js` も
作り直し、それも一緒にアップロードしてください）。

### スマホでの表示について

スマホなど画面の狭い端末で開くと、②対応表・③バーコードラベル作成のタブは自動的に非表示になり、
「①番号入力」の画面だけが表示されます（登録などの管理操作はPCで行う想定のため）。また、
「🖨️ 印刷する」ボタンはPC向け（プリンターに接続している想定）のため、スマホでは表示されません
（「PNGをダウンロード」または「新しいタブで開く」で保存できます）。

※スマホでちゃんと写真が表示されるのは、`mapping.js`（＋`photos-data.js`）に登録されている
番号だけです。PCの「一時登録」だけで登録したものは、下の「一時登録をスマホなど他の端末にも
反映させる（書き出し機能）」の手順でmapping.jsに書き出してアップロードするまでスマホには出てきません。

## 実際の写真が届いたら（対応表の登録）

`mapping.js` を開いて、以下の形式で「番号」と「写真ファイル」を書き並べてください。
1枚だけの場合は `photo`、複数枚を1つの番号に対応させたい場合は `photos`（配列）を使います。

```js
window.BARCODE_MAP = [
  {
    barcode: "0001",                // 対応させたい番号（①タブで入力する値）
    photo: "photos/product001.jpg", // 1枚だけの場合
    label: "商品名など（任意）"
  },
  {
    barcode: "0002",
    photos: ["photos/product002_1.jpg", "photos/product002_2.jpg"], // 複数枚の場合
    label: "商品名など（任意）"
  },
  // ...必要な数だけ追加
];
```

- 写真ファイルは `photos` フォルダにコピーしてください（jpg/png対応）
- `barcode`（番号）は入力された文字列と完全一致で照合します（前後の空白は自動で無視されます）。
  数字だけでなく、任意の文字列（`SAMPLE-0001` のような形式）も使えます
- **`photos` フォルダの中身を追加・変更したら、次のコマンドを1回実行してください**（Pythonが入っているPCの場合）。
  レシート画像の「PNGをダウンロード」や「グレースケール／白黒2値」表示を正しく動かすための下準備です（`photos-data.js` を作り直します）。

  ```
  cd receipt-photo-system
  python3 tools/build_photos_data.py
  ```

- 保存・実行して `index.html` を再読み込みすれば反映されます
- 私（Claude）に写真一覧とファイルをお送りいただく運用の場合は、`mapping.js` の更新とあわせてこのコマンドもこちらで実行してからお渡しします。自分で編集されない場合は特に気にしていただく必要はありません。

番号と写真の対応リスト（Excel/CSVなど）をいただければ、私の方で `mapping.js` に
反映することも可能です。その場合は「①どの番号に②どの写真ファイルを対応させるか」が
わかる一覧と、写真ファイル一式をお送りください。

## 動作確認用のミニ機能

- **②対応表タブの「一時登録」**: その場で好きな写真（複数枚選択可）をアップロードして番号と
  紐付けられます。**このPC・このブラウザに保存されるため、ページを再読み込みしても消えません。**
  ただし**この保存場所はブラウザごとに別々**なので、PCで一時登録しただけではスマホ側には表示されません。
  不要になったら、一覧の写真サムネイルの「×」で1枚だけ削除、「登録を削除」で番号ごとまとめて
  削除、「一時登録をすべて削除」で全件削除できます。
- **一時登録をスマホなど他の端末にも反映させる（書き出し機能）**: 一時登録の下にある
  「mapping.js と photos-data.js を書き出す」ボタンを押すと、今の対応表（mapping.js）＋一時登録の
  内容をまとめた `mapping.js` と `photos-data.js` の2ファイルがダウンロードされます。これをGitHubの
  同名ファイルに上書きアップロードして数分待てば、スマホを含めてどの端末でページを開いても同じ写真が
  表示されるようになります（この2ファイルだけで完結するので、`photos` フォルダへの画像追加は不要です）。
  反映を確認できたら、「一時登録をすべて削除」でこのブラウザ内の一時登録を消して整理しておくと安全です
  （消さなくても動作上は問題ありませんが、対応表タブの表示が二重に見えることがあります）。
- **③バーコードラベル作成タブ**: 対応表に登録した番号を、実際に商品や券に貼るバーコード
  ラベルとして画像化・印刷できる補助機能です。将来バーコードリーダー（ハードウェア）を
  導入したときに読み取れるよう、あらかじめラベルを用意しておく用途を想定しています。
  ①タブでの番号入力はこの画像を使わず番号をそのまま入力する運用なので、この機能を
  使わなくてもシステム自体は問題なく使えます。

## 複数の番号を1枚のレシートにまとめる

「①番号入力」タブは、番号を入力するたびに画面右の「追加した一覧」に1件ずつ追加していく
仕様です。続けて何個でも番号を入力できます。

一覧にたまった番号は、行の「削除」ボタンで個別に取り消せます。入力したいものが
すべてそろったら「レシートを作成」を押すと、一覧の内容（各番号の写真・ラベル・
バーコード画像）をすべて1枚のレシートにまとめてプレビューします（1件だけの場合も同じ
操作で問題なく作成できます）。

プレビュー画面で「これでOK」を押すと履歴に記録され、一覧はクリアされます。「やり直す
（一覧に戻る）」を押した場合は一覧の内容は消えないので、番号を追加・削除してから
もう一度「レシートを作成」をやり直せます。「一覧をクリア」で一覧を空に戻すこともできます。

## レシートのデザインについて

上下端はまっすぐな仕上がりで、伝票番号（No.）や日時、区切り線がモノスペースフォントで
印字されます。1つの
番号に複数枚の写真が登録されている場合は縦に並べて表示され、複数の番号を
まとめた場合は各番号の内容（写真・ラベル・バーコード画像）が区切り線を
はさんで縦に並び、上部に「点数: ◯点」も表示されます。各番号の下にはバーコード画像が
飾りとして印字されますが、これは見た目のためのものです（読み取りには使いません）。

## 印字モードについて

将来レシートプリンター（多くは感熱式・白黒）で印刷することを想定し、①タブの「印字モード」で
カラー／グレースケール／白黒2値（感熱プリンター風の見え方）を切り替えてプレビューできます。
実際に使うプリンターの仕様（用紙幅・解像度・白黒/カラー）が分かれば、より正確に調整できます。

PCでプリンターに接続している場合は、レシートプレビューの「🖨️ 印刷する」ボタンから
そのまま印刷ダイアログを開けます（新しいタブでレシート画像を開き、自動的に印刷ダイアログを
表示します）。
