# バーコード連動レシート写真システム

プリンターやバーコードリーダーがまだ無い段階で、PCのカメラを使ってバーコードを読み取り、
対応する写真から「レシートに印字するイメージ」を作成・確認できる試作アプリです。
サーバー不要・PCのブラウザだけで動作します。

## 使い方（最短）

1. `receipt-photo-system` フォルダを丸ごとPCに保存する
2. `index.html` をダブルクリックして Google Chrome で開く
3. 「①スキャン確認」タブで「カメラ開始」を押す（カメラ使用の許可を求められたら許可）
4. まだ本物のバーコードが無い場合は、先に「③テスト用バーコード作成」タブで
   サンプルバーコード（SAMPLE-0001 など）を画面に表示し、スマホやタブレットに
   映してPCのカメラで読み取ってみてください
5. 対応する写真が見つかると、右側にレシートのプレビューが表示されます
   「これでOK」で履歴に記録、「やり直す」で取り消し、「PNGをダウンロード」で画像として保存できます

対応ブラウザは **Google Chrome推奨**です（Edgeでも動作しますが、Chromeで動作確認しています）。
インターネット接続が必要です（バーコード読み取り・作成ライブラリをCDNから読み込むため）。

**スマホで使いたい場合**は、上記の方法（`index.html` を直接開く）ではカメラが使えません。
下の「スマホで使う（一時公開・アカウント不要）」をご覧ください。

## スマホで使う（一時公開・アカウント不要）

スマホのブラウザでカメラ（`getUserMedia`）を使うには、`index.html` を直接開く方式（`file://`）ではなく、
**`https://` で配信されたページ**である必要があります（Safari・Chromeどちらも同様の制限があります）。
そこで、PC上でこのフォルダを一時的にWeb公開して、そのURLをスマホで開く方法を使います。
無料・アカウント登録不要の「Cloudflare Quick Tunnel」という仕組みを使います。

**注意**: 発行されるURLは推測されにくいランダムな文字列ですが、稼働中は誰でもアクセスできる状態になります。
検証用の一時的な仕組みなので、使い終わったら両方のターミナルを閉じて（`Ctrl + C`）公開を止めてください。
再度起動するとURLは毎回変わります。ずっと同じURLで使いたい場合は、無料の静的ホスティング
（Cloudflare Pages・GitHub Pagesなど）への常設公開をご検討ください（ご希望であれば別途ご案内します）。

### 手順（Mac / ターミナルを2つ使います）

**ターミナル1: ローカルサーバーを起動**

```
cd receipt-photo-system
python3 -m http.server 8000
```

そのまま起動したままにしておきます（閉じないでください）。

**ターミナル2: 公開用トンネルを起動**

`cloudflared` がまだ無い場合は、最初に1回だけインストールします（Homebrewがあれば）。

```
brew install cloudflared
```

（Homebrewが無い場合は https://github.com/cloudflare/cloudflared/releases から
`cloudflared-darwin-amd64.pkg`（Intel Mac）または対応するパッケージをダウンロードしてインストールしてください。）

インストールできたら、トンネルを起動します。

```
cloudflared tunnel --url http://localhost:8000
```

しばらくすると、ターミナルに `https://◯◯◯◯.trycloudflare.com` のようなURLが表示されます。
このURLをスマホのブラウザ（Safari / Chrome）で開いてください。Wi-Fiでもモバイル回線でもアクセスできます。

### スマホでの使い方

1. 上記のURLをスマホのブラウザで開く
2. 「①スキャン確認」タブで「カメラ開始」をタップし、カメラ使用を許可する
3. バーコードを読み取ると写真付きレシートのプレビューが表示される
4. 「これでOK」で確定、「PNGをダウンロード」で保存
   - **iPhoneでダウンロードがうまく動かない場合**は、隣の「新しいタブで開く（iPhoneは長押しで保存）」を
     使ってください。画像だけが表示されるので、長押しして「写真に追加」または「画像を保存」を選べば保存できます。

## 常時公開する（GitHub Pages・無料アカウント要）

「毎回トンネルを起動するのが面倒」「いつも同じURLでスマホからアクセスしたい」という場合は、
GitHub Pages でこのフォルダを常設公開できます。無料のGitHubアカウントが必要です。

**重要な注意**: GitHub の無料プランでPagesを公開するには、リポジトリを **Public（公開）** に
する必要があります。Publicにすると、このフォルダの中身（写真も含む）は **URLを知っていれば誰でも
閲覧できる状態** になります。有料プランでもリポジトリをPrivateにできるだけで、公開されたサイト自体の
閲覧に認証をかけるにはGitHub Enterpriseが必要です。今はサンプル写真だけですが、実際の写真を
登録して常設公開する場合はこの点にご注意ください（非公開にしたい場合は、都度公開する
Cloudflare Quick Tunnel運用のままにするか、Cloudflare Pages + Cloudflare Access
のようなアクセス制限付きの方法をご検討ください。ご希望があればそちらの手順もご用意します）。

### 手順（ブラウザだけ・gitコマンド不要）

1. https://github.com で無料アカウントを作成してログインする
2. 右上の「+」→「New repository」で新しいリポジトリを作成する
   - Visibility は **Public** を選ぶ（Privateだと無料プランではPages公開できません）
3. 作成したリポジトリの画面で「Add file」→「Upload files」を開く
4. この `receipt-photo-system` フォルダの**中身**（`index.html`・`app.js`・`style.css`・
   `mapping.js`・`photos-data.js`・`.nojekyll`・`README.md`・`photos`フォルダ・`tools`フォルダ）を
   まとめてドラッグ&ドロップする（フォルダごとではなく、中身を選んでください）
5. 画面下の「Commit changes」でアップロードを確定する
6. リポジトリの「Settings」→左メニューの「Pages」を開く
7. 「Build and deployment」の Source を **「Deploy from a branch」**、
   Branch を **「main」/「/(root)」** にして「Save」
8. 1〜3分待つと、ページ上部に `https://ユーザー名.github.io/リポジトリ名/` というURLが表示される
9. そのURLをスマホのブラウザで開けば、PCと同じ操作（カメラ開始→読み取り→確認→ダウンロード）が使えます

写真や対応表(`mapping.js`)を更新したときは、同じ「Add file」→「Upload files」で該当ファイルを
アップロードし直せば数分後にサイトへ反映されます（`photos`フォルダの画像を追加・変更した場合は、
アップロード前に手元で `python3 tools/build_photos_data.py` を実行して `photos-data.js` も
作り直し、それも一緒にアップロードしてください）。

## 実際の写真が届いたら（対応表の登録）

`mapping.js` を開いて、以下の形式で「バーコードの値」と「写真ファイル」を書き並べてください。
1枚だけの場合は `photo`、複数枚を1つのバーコードに対応させたい場合は `photos`（配列）を使います。

```js
window.BARCODE_MAP = [
  {
    barcode: "4912345678904",       // バーコードに埋め込まれている値（スキャンされる文字列）
    photo: "photos/product001.jpg", // 1枚だけの場合
    label: "商品名など（任意）"
  },
  {
    barcode: "4912345678911",
    photos: ["photos/product002_1.jpg", "photos/product002_2.jpg"], // 複数枚の場合
    label: "商品名など（任意）"
  },
  // ...必要な数だけ追加
];
```

- 写真ファイルは `photos` フォルダにコピーしてください（jpg/png対応）
- `barcode` は読み取られた文字列と完全一致で照合します（前後の空白は自動で無視されます）
- **`photos` フォルダの中身を追加・変更したら、次のコマンドを1回実行してください**（Pythonが入っているPCの場合）。
  レシート画像の「PNGをダウンロード」や「グレースケール／白黒2値」表示を正しく動かすための下準備です（`photos-data.js` を作り直します）。

  ```
  cd receipt-photo-system
  python3 tools/build_photos_data.py
  ```

- 保存・実行して `index.html` を再読み込みすれば反映されます
- 私（Claude）に写真一覧とファイルをお送りいただく運用の場合は、`mapping.js` の更新とあわせてこのコマンドもこちらで実行してからお渡しします。自分で編集されない場合は特に気にしていただく必要はありません。

バーコード値と写真の対応リスト（Excel/CSVなど）をいただければ、私の方で `mapping.js` に
反映することも可能です。その場合は「①どのバーコード値に②どの写真ファイルを対応させるか」が
わかる一覧と、写真ファイル一式をお送りください。

## 対応しているバーコード

1次元バーコードのみに対応しています（JAN/EANコード、CODE128、CODE39、UPCなど）。
QRコードなどの2次元コードは対象外です。

## 動作確認用のミニ機能

- **③テスト用バーコード作成タブ**: 実物のバーコードが無くても、任意の文字列からバーコード画像を
  作成し、画面表示・印刷ができます。これを別の画面（スマホなど）に映してPCカメラで読み取れば、
  一通りの動作確認ができます。
- **②対応表タブの「一時登録」**: 写真がまだ届いていなくても、その場で好きな写真（複数枚選択可）を
  アップロードしてバーコード値と紐付けられます。**このPC・このブラウザに保存されるため、ページを
  再読み込みしても消えません。**（別のPCやブラウザには引き継がれません）
  不要になったら、一覧の写真サムネイルの「×」で1枚だけ削除、「登録を削除」でバーコードごとまとめて
  削除、「一時登録をすべて削除」で全件削除できます。
  ※あくまで動作確認用の保存場所です。本番運用のデータは `mapping.js` と `photos` フォルダに
  反映してください（複数の写真を安定して保存・共有するにはそちらが確実です）。

## レシートのデザインについて

上下端がミシン目で切り取ったようなギザギザになっており、実際のレシート用紙に近い見た目に
しています。伝票番号（No.）や日時、区切り線、「ありがとうございました」の一言もモノスペース
フォントで印字され、1つのバーコードに複数枚の写真が登録されている場合は縦に並べて表示されます。

## 印字モードについて

将来レシートプリンター（多くは感熱式・白黒）で印刷することを想定し、①タブの「印字モード」で
カラー／グレースケール／白黒2値（感熱プリンター風の見え方）を切り替えてプレビューできます。
実際に使うプリンターの仕様（用紙幅・解像度・白黒/カラー）が分かれば、より正確に調整できます。

## カメラが起動しない場合

- ブラウザのアドレスバー付近に出るカメラ許可ダイアログで「許可」を選んでください
- 一度拒否してしまった場合は、ブラウザのサイト設定からカメラ許可をリセットしてください
- `index.html` を直接開く方法でカメラが動作しない場合は、フォルダ内で以下のようにローカルサーバーを
  起動してから `http://localhost:8000` を開いてみてください（Python が入っているPCの場合）。

```
cd receipt-photo-system
python3 -m http.server 8000
```
